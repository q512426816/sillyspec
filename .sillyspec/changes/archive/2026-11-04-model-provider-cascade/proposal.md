# 提案书（Proposal）— 2026-11-04-model-provider-cascade

## 动机

任务原话转写：会话配置条供应商模型级联重做：模型随供应商自动选中并成对上送

动机（用户原话定调）：模型「默认」项应只在供应商=不指定时可选；选了具体供应商要直接选中上次页面上选择此供应商的模型值，没记录就选第一个——否则很奇怪。生产实证缺口：会话 provider 为 NULL 时配置条显示引擎默认供应商+其模型候选（2026-10-28 仅显示层回退），用户点模型只暂存 model，发送载荷 companion 取 session.llm_provider_id ?? "" 落空串 → 后端 inject.py:142 守卫 422「模型依赖供应商」三连拒（会话 edf0c569）；且发送失败仅面板顶部横幅，用户无感。

成功标准：
- 供应商选择（暂存/预会话/即时三模式）时模型自动选中：该供应商上次显式选过的模型（浏览器本地记忆，无效则回退）→ 无记录取候选第一个 → 无候选为空（跟随）
- 模型下拉在选中具体供应商时不再提供「默认」选项；「不指定」态维持现状（模型选择隐藏即默认语义）
- 显式选模型时记忆 供应商→模型（localStorage）
- 会话 provider NULL 时点选模型，暂存配置成对携带显示层供应商 id（engineDefaultProvider），发送载荷不再 422
- 发送失败（含 422）即时 toast 提示后端错误信息（面板三发送点位+悬浮窗两点位）
