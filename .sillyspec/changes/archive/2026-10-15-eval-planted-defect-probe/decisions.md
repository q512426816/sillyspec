# 决策记录（Decisions）— 2026-10-15-eval-planted-defect-probe

## D-001@v1: 设计期风险与放弃方案（底稿）
- 类型：process
- 状态：confirmed
- 答案：- **最大风险：隐含面的「合理解」被认为不够唯一**（判分公平性）。若 B 臂实现选择另一种可辩护读法（如把未闭合 START 按「到文件末尾」计时长）会误判为失败。缓解：①五类输入全部选了唯一合理解——「未闭合不计时长」是统计语义下唯一不捏造数据的读法（捏造结束时刻无依据）；②instruction 明确「rounds=完成轮数、totalSeconds=完成轮次时长之和」，未完成轮次不属于"完成"是字面推论；③真跑前由人工抽看 A/B 失败 workdir 的 stderr 定位（verify 逐断言可定位）。 - **设计迭代留痕（fixture v1 → v2，判分公平性红线的自我纠察）**：初版 fixture 做了**全行序打乱**——部分 END 行在文件序上先于自己 session 的 START 出现，这使「单遍扫描按 (sessionId,phase) 配对」这一最合理解必然漏配（solution 参考解自己就挂了，测试当场暴露）。全乱序下"先按时间戳排序再配对"与"单遍文件序配对"两种读法都有可辩护性，违反本条唯一性红线——已修正为**交错乱序**：跨 session 事件交错 + 行时间戳非单调（保住"行序≠时间序"的隐含面），但各 session 自身的 START 恒先于自己的 END（保住单遍配对解的唯一性）；未闭合/孤儿/多轮/空行/空白行五类隐含面全部保留，naive 判别力经测试复核不变。 - **次风险：naive 实现恰好蒙对**（判别力失真）。naive 若按行序邻接配对：首个 END（s3）在其 START 之前到达——邻接栈实现会跳过或错配，空白行会让 split 解析出 undefined 字段——无论崩溃还是错值，verify 必拒；测试钉死后该性质受回归保护。 - **评测口径风险**：B 臂轻量道（flow start）对这种小任务不经过 plan 阶段的 Review Focus 节——首轮实测若两臂无差异，可能归因于「B 臂没走到机制」而非「机制无效」。这不是本变更缺陷而是解读注意事项：届时应改用走完整 plan 流程的任务形态（或 B 臂 prompt 指定 run plan）再下结论。已记入本节供首次实测者参考。 - **放弃的方案**： - *glob 匹配题材*（镜像本仓 2026-10-15-module-path-glob-match 真实故障）：`*` 是否跨目录在业界存在正当分歧（minimatch vs bash），作为"隐含唯一解"不成立——弃。 - *在 verify.mjs 里按隐含面分组计分*（如输出各盲区命中明细）：verify 契约是退出码 0/非 0（runner 口径），分组计分需要动 eval 工具链——超出本变更边界；失败定位已由逐断言 stderr 覆盖。 - *给 instruction 加「数据可能有脏行」级别的弱提示*：会直接泄题，摧毁探针的判别力——禁区。
