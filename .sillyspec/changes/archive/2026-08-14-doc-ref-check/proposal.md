# Proposal — 文档行号引用校验脚本（doc-ref-check）

## 背景

`docs/sillyspec/platform-interface-map.md` 是本仓的「平台接口操作地图」，内含 60+ 处 `file:line` 源码引用作为溯源依据。经 2026-08-14 多轮人工核对发现：文档是源码的二级抽象，行号会随源码增删漂移、且无任何自动检测——只能靠人工反复核对，且每轮都能查出问题。

## 目标

把「文档行号引用与源码一致性」变成 `npm test` 可自动校验的硬门：行号漂移（文件删改名 / 行号超界 / 引用指向的行内容与文档断言的关键词对不上）→ 测试红灯 → CI 阻断。

## 方案概述

新增单文件 `test/doc-ref-check.test.mjs`（方案 A，用户确认）：
1. **提取层**：正则提取文档中所有 `路径.js:行号` / `:起始-结束` 引用；裸文件名在 `src/` 递归定位（唯一命中才通过）。
2. **断言层**：存在性硬校验（文件存在 + 行号边界）+ 代码符号关键词断言（引用附近反引号 token 像代码符号时，断言源文件对应行 ±1 内含该 token）。
3. **接入**：`.test.mjs` 被 `test/run-tests.mjs` 自动收集 → 进 `npm test`，零侵入 CI。

## 不在范围内（Non-Goals）

- **不校验其他文档**（docs/sillyspec/*.md 其余文件、docs/prompt/）——后续渐进套用，本次仅 platform-interface-map.md（用户选择：薄脚本见效快）。
- **不抓「行号未变但语义已变」**——代码同位置内容重构后语义漂移需人工 review，非本工具能力。
- **不修改 docs/prompt/_verify.mjs**——那是 fence 逐字对比语义，与本工具（行号断言）不同，不合并。
- **不接 GitHub Actions**——本仓 CI 即 `npm test`（pre-push hook），接入 npm test 即接入全部现有门禁。
- **不做快照式全文校验**（把源文件行内容快照进文档逐字对比）——维护成本高，关键词断言已满足检测需求。

## 成功标准

1. `npm test` 中 doc-ref-check 用例全绿（当前文档行号全部有效）。
2. 人为把文档中某行号 +10（模拟漂移）→ 测试变红并精确指出失效引用。
3. 删除一个被引用文件（模拟）→ 测试变红。
