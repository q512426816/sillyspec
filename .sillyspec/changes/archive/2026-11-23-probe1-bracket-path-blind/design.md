# 设计记录（Design Record）— 2026-11-23-probe1-bracket-path-blind

## 做法概述

本变更怎么解决问题？改哪里、为什么选这个方案（一两段）。

两处改动，都在 `src/verify-probes.js`。其一，探针 1 主循环改为「字面路径优先」：先剥 `NEW:` 前缀，再按字面路径解析（主仓存在→扫描；主仓缺失但 worktree 存在→扫描并计 `worktreeHits`），两处都不存在时才判通配符入 `globEntries`，无通配才入 `skippedFiles`。原逻辑先判 `/[*?[\]]/` 再判存在，导致 `[id]` 这类字面路径永远被跳过。其二，`renderVerifyProbesReport` 收紧结论：`matches` 为空时不再无条件打 ✅，仅当 `globEntries` 与 `skippedFiles` 也全空才输出全清结论，否则输出 ⚠️「结论不完整」。选择「字面存在优先」而非解析方括号内容，是因为 `[id]` 与 `[a-z]` 形态相似、正则判不准；一次 `existsSync` 即可覆盖 Next.js / Vue 动态路由，且对真 glob（字面不存在）零影响。

## 边界与并发（盲维四问——每问必答，答不了即设计缺口）

1. 乱序/迟到到达：输入或事件乱序时，本设计的假设还成立吗？

   答：design 清单顺序不影响结果；同一路径重复列出会重复扫描（既有行为，本变更不改变）。文件内容随时间变化属正常输入面，下一次 verify 重跑即刷新。

2. 并发写：两个执行体同时操作同一数据/文件会发生什么？

   答：探针为纯只读扫描，无写路径；扫描期间文件被并行会话改写可能读到中间态，只影响本次报告，不产生持久副作用，重跑修正。

3. 切换/生命周期：会话、请求或变更中途切换/中断时状态是否安全？

   答：探针无跨调用状态；worktree 存在性按扫描时刻判定，与 init 时刻不同会导致 `worktreeHits` 漂移——此维度已在既有对账中排除（R-02），本变更不新增漂移面。

4. 作用域：跨工作区/跨仓/多实例时数据会不会串台？

   答：路径一律相对 `cwd` / worktree 根解析，不跨仓、不跨工作区；「字面存在优先」只在 design 清单声明的路径集合内生效，不改变其他探针。

## 风险与死路

本方案最大的风险是什么？试过但放弃的方案及放弃理由？

最大风险：用户本想写 glob（如 `src/[a-z].ts`）且恰好存在同名字面文件时，会被当字面扫描。概率极低，且「字面存在即扫」比猜测用户意图更符合最小惊讶；真 glob 一般不会被字面命中。

放弃方案 A：解析方括号内容判断是否 glob 字符类——`[id]` 与 `[a-z]` 形态相似，正则判不准，反而制造新误判。

放弃方案 B：引入 glob 库做完整展开——新增依赖与展开面控制成本，本变更只需覆盖动态路由这类字面目录；真 glob 继续交 agent 展开符合现行设计。

放弃方案 C：只改报告措辞、不改扫描——治标不治本，隐藏的 TODO 仍然扫不到，本次事故正是如此发生的。
