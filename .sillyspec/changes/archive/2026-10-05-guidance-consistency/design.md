## 做法概述

本变更怎么解决问题？改哪里、为什么选这个方案（一两段）。

两处指引文本对齐实态：① AGENTS.md 是 agent 会话的第一入口（init 生成可自由编辑），在其轻量道两处 `--input` 提法旁补一句过门格式要点（「成功标准：」独立成行、每行一条 `- <可验证标准>`）——格式门实现在 flow start（报错文案已含格式说明但那是事后），前置到入口文档使首调即过；② src/run/command.js 只读短路块注释的「status/doctor」改为「status」并注明 doctor 移出史（2026-09-09-doctor-noai，与 constants.js 常量内注释同口径）。选注释就地修正而非删除：该块注释承载 D-005@v2/FR-04 的决策出处，纠正覆盖面表述即可保留出处价值。

## 风险与死路

本方案最大的风险是什么？试过但放弃的方案及放弃理由？

最大风险：AGENTS.md 格式要点若与 flow start 格式门未来演进不同步会变成第二份漂移文档——以「要点级」而非「全文复制」表述（只写行形态不复制报错全文），漂移面最小化。放弃的方案：把格式说明同时写进 flow start 的 --help 输出（入口更近）——该输出文案在 flow.js（并行会话在途），本轮不可触碰；AGENTS.md 已是可动的最近入口，help 面留给在途落盘后。
