# 提案书（Proposal）— 2026-10-05-hunk-gate-commit-attribution

## 动机

任务原话转写：hunk 归属门对已归档他侧交付误报「未归因」（F-4，2026-10-05 本会话实证：flow done 对账输出「未归因：src/ui-visual.js…属并行会话在途交付则须 pathspec 隔离；属本变更则补 design 自声明」双误导——实为他侧已归档变更 546720ea 的交付，非在途非本变更）。根因：collectForeignDeclarations 只扫活跃变更声明面（排 archive/），归档后声明面失效；而 patch 冻结面（filterCommittedFace）同窗口已按提交事实归属正确剔除该文件——两个消费点口径不一。修法：对账的未归因判定补提交事实归属切分（commitAttributionForChange+isForeignByCommit 同源）：窗口内全部提交均属他侧变更名的文件改判「他侧归因（提交事实）」ℹ️ 信息行（不计数 ok 阻断面）；裸提交/本变更名提交触碰的文件保持未归因 fail-closed 原口径。
成功标准：
- 已归档他侧交付（窗口内全部提交属他侧变更名）不再报未归因，改报「他侧归因（提交事实）」信息行并注明 patch 冻结面同口径剔除
- 他侧归因文件不计入 ok 阻断面（gate=error 不再因此拦）；裸提交/本变更名提交的文件维持未归因原判定
- 归属切分不可得（非 git/无基线/git 失败）时保持原口径全量未归因（fail-closed 不放宽）
- 单测覆盖：他侧归因改判/裸提交维持/切分不可得退化三形态
