## 做法概述

本变更怎么解决问题？改哪里、为什么选这个方案（一两段）。

纯提示词层改动（无逻辑/门禁/格式变化）。根因：两处规则源口径相反——`src/ui-visual.js` flow start 须知（2026-09-27-ui-visual-guidance，引 frontend-apple-style 实证）要求定稿原型为可复跑真码产物、手绘仅限粗选；而 `src/stages/brainstorm.js`「生成要求」字面指令「独立的 HTML 文件（内联 CSS+JS）、单文件浏览器直接打开」。步骤 prompt 在执行现场 Always 在场，flow start advisory 早已淡出——agent 照步骤 prompt 产手绘假 HTML。做法：brainstorm 生成要求重写为真码五要素（同方言/可复跑/手绘仅粗选+实证锚/单文件方言例外/降级裁决出路），explore 原型节定位粗选件并写明交接升级（手稿≠定稿），design-facts 自审清单同步；新增测试把 brainstorm prompt 与 `buildUiGuidanceLines()` 用共享关键词（真码/粗选/工具链）锁成同源——这是防复潮关键：两处规则源再漂移会红。分级档位（是否生成）、`prototype-<名称>.html` 命名、execute.js 注入逻辑零改动。

## 风险与死路

本方案最大的风险是什么？试过但放弃的方案及放弃理由？

- 风险1：真码要求抬高 brainstorm 产出成本，粗选场景被过度工程化。对策：明确手绘单文件在粗选/对比场景合法（explore 全程合法、brainstorm 粗选合法），只有定稿须真码。
- 风险2：无前端工程的项目（纯静态站）被误伤。对策：单文件 HTML 方言例外显式写明。
- 风险3：无 HTML 运行面的平台（小程序原生）无法满足。对策：降级声明+用户裁决留痕出路，与既有「UI 视觉证据」探针 error 门（ui-visual.js）同机制衔接，不新造门。
- 死路：考虑过在 gates.js 加「原型文件不含项目组件引用即 warn」的内容嗅探——放弃：嗅探需解析任意方言 HTML/JSX，误判面大且仓中立不可行；关键词同源测试已把两处规则源锁定，语义执法留给收口探针与独立评审。
