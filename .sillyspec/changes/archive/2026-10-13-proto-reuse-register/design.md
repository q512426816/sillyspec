# 设计记录（Design Record）— 2026-10-13-proto-reuse-register

## 做法概述

本变更怎么解决问题？改哪里、为什么选这个方案（一两段）。

纯提示词与提醒文案层改动（无状态机、无新文件格式、无 CLI 命令变化）。`src/stages/brainstorm.js`「HTML 原型分级」表在必须生成/建议生成/跳过三档之外加「免生成·登记复用」档：用户已提供可复跑 HTML 原型且覆盖本次 UI 面 → 免重画，但必须复制进变更目录并按 `prototype-<名称>.html` 命名（execute.js:957 按此命名扫描注入，命名即契约）+ 声明来源与覆盖面；静态截图/设计稿不可复跑，明确排除在本档外。操作第 6 条、铁律、输出契约由二选一同步为三选一。周边四处（brainstorm-auto 原型节、explore 复制复用行、gates 软提醒文案、design-facts 自审清单项）同步口径。依据：2026-10-10-fire-equipment dogfood 实证——用户已给 4497 行终稿原型，agent 只能按精神走「跳过」且不登记，execute 注入（按 prototype-*.html 命名）全程不生效，对照靠 prompt 临时绝对路径，跨会话即断。

execute.js 注入逻辑不动——它是命名约定的消费端，已是正确实现；本变更把生产端（brainstorm 指引）对齐到同一契约。

## 接口契约

动了哪些函数/端点/命令/文件格式？对外可见的签名或行为变化是什么（含「无」的说明）？

- 无函数签名变化、无 CLI 命令/flag 变化、无文件格式变化。
- `gates.js` `warnMissingUiPrototype`：仅 console.warn 文案追加登记复用出路；判定条件（design.md 命中前端扩展名 且 变更目录无 prototype-*.html）不变。复用登记正确的变更，目录必有 prototype-*.html，软提醒自然静默；声明复用但忘复制则提醒照响——正是要兜的坑。
- 各 stage prompt 字符串内容变化（对 agent 的指引面），docs/prompt/*.md 派生文档同步。

## 边界与并发（盲维四问——每问必答，答不了即设计缺口）

4. 作用域：跨工作区/跨仓/多实例时数据会不会串台？

3. 切换/生命周期：会话、请求或变更中途切换/中断时状态是否安全？

2. 并发写：两个执行体同时操作同一数据/文件会发生什么？

1. 乱序/迟到到达：输入或事件乱序时，本设计的假设还成立吗？

1. 乱序/迟到到达：提示词是静态文本，无时序假设；不适用。
2. 并发写：登记复用（复制文件进变更目录）与新生成互斥于同一变更的三选一决策内，同一生成不会同时走两档；最坏情形同名覆盖，与现状生成路径风险相同，无新增并发面。
3. 切换/生命周期：登记复用把原型固化进变更目录（相对路径、随变更归档走），比现状的绝对路径引用更抗会话切换与机器迁移；无状态迁移。
4. 作用域：`prototype-*.html` 命名约定是 sillyspec 全局约定，平台模式 specRoot 下 changeDir 解析由现有注入代码处理（execute.js 相对拼接），不新增作用域分叉。

## 风险与死路

本方案最大的风险是什么？试过但放弃的方案及放弃理由？

- 风险1：agent 登记复用时复制了但改名不规范（保留中文原名）→ execute 不注入。对策：分级文本把命名写成硬要求 + design-facts 清单复核命名 + gates 软提醒兜底（目录无 prototype-*.html 即响）。
- 风险2：既有原型只覆盖部分 UI 面（如只覆盖 PC 无小程序）。裁决：覆盖面声明必须如实写，未覆盖部分仍按「必须生成」产出增量原型；变更目录本就允许多个 prototype-*.html 共存，execute 注入支持多文件。
- 死路：考虑过让 gates 硬校验 design.md 中「复用声明」的格式——放弃：复用声明是自由文本，硬校验只会催生占位应付，软提醒+自审清单已与「跳过原因」同等强度，够了。
