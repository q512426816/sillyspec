# 设计记录（Design Record）— 2026-10-12-review-na-variant

## 做法概述

本变更怎么解决问题？改哪里、为什么选这个方案（一两段）。

实证两仓 349 个轻量变更中 12/228 的实质作答误升级：整体不适用声明写成「四问全 n/a：纯 CSS 类…」「均不适用…」「边界并发四问：不适用：纯文案/默认值改动…」等前缀而非「不适用」开头，被 `flow-review.js` 两处 `/^不适用/` 机械判成实质作答、触发信号②升级评审（误伤样例：平台仓 `2026-09-27-hover-polish` 纯 CSS 变更起子代理评审）。修法：改 `src/flow-review.js`——新增单一判定 helper（模块内 `NA_ANSWER_RE` + 判定函数），v1 槽3 分支与 v2 节分支同源调用；窄口径正则只认整声明开头：可选前缀（盲维四问/边界并发四问/四问）+ 可选冒号 + 可选限定词（全部/均/皆/都/全）+ 「不适用」或「n/a」（`\b` 界定、不分大小写）。选此方案因为判定面只动评审定档一处：`DESIGN_QUESTIONS` 锚、draft ledger、剥题逻辑三个消费面零波及，无在途 v2 兼容问题（改问题文案则要付 stripV2QuestionLines 逐字剥题的在途代价）；前缀声明语义与现行 `/^不适用/` 同型——现状「不适用，但…」本就按开头豁免，本变更加宽词表不加新语义维度。逐问否定聚合判定被否：判定复杂化引入新误判面，且该形态作答常含逐维实质推理（如 takeover 系「409 先于写库无半成品」），升级是设计内行为。

## 风险与死路

本方案最大的风险是什么？试过但放弃的方案及放弃理由？

- 最大风险：豁免面扩大=漏报面扩大——「n/a，但并发写存在竞态…」这类声明开头后跟实质内容的作答会被豁免。对冲：①该弱点与现行 `/^不适用/` 完全同型（现状「不适用，但…」同样豁免），本变更未引入新弱点类别；②豁免面有 1/4 抽查采样 + 承诺词/diff 原语/edit_ratio 三路独立信号兜底；③抽查评审检查单第 2 问专查「说不适用的维度 diff 真没有该风险面吗」。
- 死路①：改 `DESIGN_QUESTIONS` 引导文案教 agent 写规范形态——问题文本/引导行在锚定与剥题消费面，改一行付在途 v2 兼容代价（`stripV2QuestionLines` 用当前常量逐字剥题，旧稿漏剥会误扫/误豁免）；判定端宽容词表是零兼容成本的对面。
- 死路②：逐问否定聚合判定（四问全 n/a 才豁免）——逐问解析引入新误判面（混合形态、否定词形变），窄口径已覆盖实证的全部 12 例误伤，复杂度不值。
- 死路③：测试绑定「不适用」口径（`flow-draft.js:647/670`）同步放宽——绑定面「不适用」语义是「无测试面」，与评审豁免声明是不同物，混一处放宽让无测试 FR 的语义漂移。
