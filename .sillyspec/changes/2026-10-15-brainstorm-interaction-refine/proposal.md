# 提案书（Proposal）— 2026-10-15-brainstorm-interaction-refine

## 动机

任务原话转写：头脑风暴交互精化：对照 Superpowers v7.0.0 brainstorming 重写，补齐需求确认的来源标记、分块回放、builder 视角与自欺逃逸口表（只改 brainstorm 阶段产出与交互约束，不新增步骤、不动状态机）

动机：与 Superpowers（obra/superpowers）v7.0.0 的 brainstorming 逐节对照后发现四个可迁移的差异面：①需求确认清单一次性成型、未标注哪些是用户原话哪些是 agent 推断，用户无从分辨哪些点其实还需要点头（反向印证纪要 2026-09-29-brainstorm-exit-thin-default 已把「纯凭自身判断直接放行」列为逃逸口）；②回放时机晚——理解分块回放的纠错成本远低于整份清单，而现有步骤已具备 repeatableWait 重入能力却未利用；③Design Grill 只查「文档内部/四件套之间/与外部约束」的结构性矛盾（审查者视角），缺「照这份文档我干得下去吗」的实现者视角（Superpowers builder check，其实证为会话设计 iOS 应用却交付 web 应用）；④P1/P2 歧义逐轮问会拉长用户时间，应改为能自定的自定并标注、只有会改变产物的攒一轮收尾。

成功标准：
- 需求确认清单逐条带来源标记（用户原话/agent 推断两态），未确认过的推断点不得混入已确认清单
- 对话式探索支持分块回放：每轮输出含 200-300 字回放块（猜测标为猜测）+ 一句「哪里不对或漏了什么」，步骤保持 repeatableWait 语义
- 进入「提出 2-3 种方案」前：P1/P2 未决项为 0 或已记录为「我的判断」落 decisions.md
- 分段展示设计输出含「我替你做的决定」节，条目来源为 decisions.md 中 source≠user 的条目
- Design Grill 子代理派发 prompt 含实现者视角四要素（真身份/联系不到作者/只报猜错会出事的必须被回答项/显式跳过项与 nothing important left 出口），主代理回收后分三堆处理
- brainstorm 阶段 prompt 含自欺逃逸口对照表（三条：够清晰、太简单、用户说听起来不错）
- 发现规模超出当前档位时当场说明并给出升级建议（不改客观定价机制）
- 变更自身测试面跑绿（node --test 相关用例），lint 通过

## 变更范围

按成功标准机械推导，共 8 条验收面：
1. 需求确认清单逐条带来源标记（用户原话/agent 推断两态），未确认过的推断点不得混入已确认清单
2. 对话式探索支持分块回放：每轮输出含 200-300 字回放块（猜测标为猜测）+ 一句「哪里不对或漏了什么」，步骤保持 repeatableWait 语义
3. 进入「提出 2-3 种方案」前：P1/P2 未决项为 0 或已记录为「我的判断」落 decisions.md
4. 分段展示设计输出含「我替你做的决定」节，条目来源为 decisions.md 中 source≠user 的条目
5. Design Grill 子代理派发 prompt 含实现者视角四要素（真身份/联系不到作者/只报猜错会出事的必须被回答项/显式跳过项与 nothing important left 出口），主代理回收后分三堆处理
6. brainstorm 阶段 prompt 含自欺逃逸口对照表（三条：够清晰、太简单、用户说听起来不错）
7. 发现规模超出当前档位时当场说明并给出升级建议（不改客观定价机制）
8. 变更自身测试面跑绿（node --test 相关用例），lint 通过
