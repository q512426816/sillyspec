任务原话转写：动机：薄道治理工件三实证痛点——指纹标记污染阅读面（业务开发读不懂）、GWT 骨架预填产出占位 Then 与 80 字腰斩残次品并已归档（voluntary-task-tick 7 条）、成功标准摘录管道存在编号劫持与复合拆分与截断的静默变形。对照 OpenSpec 纯 markdown 与 SHALL 加 Scenario 排版以及自家厚道结构门禁经验重构薄道文档层：文档变纯 markdown 人类可读、防篡改锚点搬进机器态 ledger、spec 断点机器化。
成功标准：
- flow start 起草的四件文档为纯 markdown 零 MACHINE-DRAFT 指纹标记零 AGENT 槽注释
- requirements FR 骨架改为 SHALL 正文加 Scenario WHEN THEN 句式且不再机器预填 GWT 场景体
- 成功标准摘录不再做复合拆分与编号劫持与 80 字截断变形
- design 四问文本与 flow done 门禁判据由单一源常量同源供给
- 起草锚点存入 draft ledger 机器态且 flow done 做文档与锚对比输出漂移 advisory
- flow start 支持 autopilot 声明且新增 flow approve 子命令记录 spec 断点用户批准
- 未声明 autopilot 的变更在 flow done 因缺批准证据拒收
- tasks.md 保留成功标准镜像任务锚并显式允许 agent 追加细化行
- 存量指纹 ledger 在途变更走旧校验双轨不受影响
- 新增聚焦测试覆盖上述行为且既有测试回归绿
