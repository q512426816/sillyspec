## 三、P0-1 stage-runner：按阶段拆会话，CLI 做编排器（最大杠杆）

### 现状基座（已核验）

- `run auto` 已把五阶段串成流水线（`src/run/command.js:1903` runAutoMode）——但**同会话推进**，是 O(n²) 的最大化形态。stage-runner 即 auto 的"每阶段换会话"改造，auto 是天然挂点。
- CLI 本地不 spawn 会话——`src/dispatch/backends/local-agent.js:4-7` 有明确设计立场（D-007：本机 Agent tool 只有 agent 能调，CLI 进程调不了）。
- **唯一"CLI 亲自派会话"通道 = SillyHub MCP `dispatchWorker`**（review-dispatch 先例：`src/review-dispatch.js:288-303` 经 createMission+dispatchWorker 派独立 worker；`src/sillyhub-mcp/client.js:543-585` 支持 workerPrompt / worktreePath / readOnly:false）。
- handoff 交接块、stage-session ledger、execute→verify ⛔ 断崖提示全齐（complete.js:752-927、handoff.js:101）——缺的是强制力与编排自动化。

### 设计：编排不在会话里，在 CLI 的「阶段边界协议」里

**形态一（平台链路，终态）**：`run auto --stage-runner` 在每阶段收口后不渲染下一阶段首步，而是经 dispatchWorker 派**阶段薄会话**：workerPrompt = 下一阶段说明书（P0-2 瘦身版）+ 上阶段产物摘要包（见下）；CLI 进程轮询 worker 终态 → 以进度库（--done 状态）为准推进 → 派下一只。全程 5 只串行薄会话，主会话不存在。预算/超时/失败处置复用 review-dispatch 的 mission 五态状态机；后端探测复用 `dispatch/strategy.js + probe.js`。

**形态二（本机链路，无平台可用）**：阶段边界渲染"薄会话派发指令"（复用 local-agent.js 指令模板范式，**阶段粒度**而非任务粒度）：主会话只做机械中继——用本机 Agent tool 起阶段 worker（fresh context、workdir=worktree、workerPrompt 同上），worker 终态回一段摘要即弃。主会话全程只背 5 组 spawn/return 对，不背任何阶段内部历史。**与 R4 dispatch 的本质区别**：粒度=阶段（5 只串行）而非任务（execute 内 19 只扇出），且主会话禁止干活（指令文本钉死）。

**入参 = 说明书 + 上阶段产物摘要（不是全文）**：新增 stage-digest 档（复用 `src/review-material-pack.js` 的 builder 范式与字节帽纪律）：上阶段产物的章节行号索引 + 决策 ID 清单 + 未决阻断 + Wave/任务面计数，帽 ~8K 字符。worker 需要全文时按路径 Read（按需一次）。

**R5-L 教训写进 design 红线**：自治会话不得自开自会话——形态二中主会话是"指令执行者"非"决策者"（切点/入参/续跑由 CLI 渲染定死）；形态一里主会话不存在。worker 内除 execute 任务的既有 dispatch 契约外禁止再开子代理。

**A 相位（当天可收，R16 直接可用）**：①plan→execute 升 ⛔ 断崖（complete.js:752 区 execute 分支模板平移到 plan 完成分支）；②`stage.wall: advisory|hard` 配置键（缺省 advisory）：hard 档 `runStage`（stage.js:32）入口读 stage-session ledger，同 SESSION_ID 硬续墙后阶段 → exit 1 + handoff 指引；`--same-session` 逃生口；ledger 缺失/读失败 fail-open。实验者手动开新会话贴交接块即等效形态二的会话切割（R15 已示范），同时此墙是形态二落地的守门件。

### 落点

形态 A：complete.js:752 区、stage.js:32、command.js（--same-session）、config-schema.js、shared.js:1957 区（readStageWall）。形态 B：run/command.js:1903（auto 挂点）、新 src/run/stage-runner.js（边界协议+stage-digest）、dispatch/backends 复用、review-dispatch.js 状态机复用。

### 验收

- A 相位：R16 execute 段 ≤25M / 均轮 ≤170K（对照 R15 45.6M/263K）。
- B 相位：R17 `run auto --stage-runner` 无人值守跑通五阶段；编排面 token ≤3M；execute 段 ≤20M；SF/OS ≤2.3×。

### 边界与风险

- 平台链路依赖 daemon dispatch_worker schema 路径 A 预热（`isPathASupported`，sillyhub-mcp.js:96-102，SILLYHUB_PATH_A=1 可强制）——探测失败自动落形态二。
- wait 类步骤在阶段 worker 内以 `--done --answer` 合并式走（P1-2 前置依赖）。
- verify FAIL → execute --reopen 的墙后往返同样经 stage-digest 交接（重开是新薄会话，不吃 verify 会话历史）。

## 四、P0-2 说明书瘦身·模板出上下文

### 现状（已核验）

- 模板绝大部分**整段内嵌**在 prompt 字符串：brainstorm.js 四大步内嵌 125/107/100/155 行（"生成规范文件"步含 proposal/requirements/tasks 三份完整落盘模板）；plan.js 75/200/200 行。`{{include:}}` 外部模板仅 6 处 3 文件。
- M1 指纹缓存（prompt.js:1952）只省"复入重发"，**不省每轮回放**——45K 说明书 ×59 轮 ≈ 2.7M 纯模板回放税。burst 一次下发 1581 行即各步 prompt（含内嵌模板）之和。

### 改法

1. **落盘模板出上下文**：proposal/requirements/tasks/design 章节模板迁 `templates/prompts/*.md`，步骤 prompt 只留要点 + 模板路径 + "写该产物前 Read 模板一次"。模板只在真写产物的轮进上下文（一次），不再每轮回放。
2. **说明书压要点**：每步留目标/边界/完成契约/铁律，长例与重复护栏删并。
3. stage-digest builder（与 P0-1 共件）。

### 验收与边界

burst 单次载荷 ≤600 行；brainstorm+plan 合计 ≤8M。风险：agent 不读模板 → 产物格式漂移 → stage-contract validator 拦（现有门正好闭环）；M1 指纹一次性全失效（预期内）。选道分两步：brainstorm+plan 两文件试点（quick，validator 兜底），R16 过数后推 execute/verify。

## 五、P1-1 输出纪律写进铁律（R12 路径固化）

通用铁律（prompt.js:2003-2011）加一条（一处改动全阶段生效）：预计输出 >50 行的命令一律 `> .runtime/logs/<名>.log 2>&1` 落盘、只回看 `tail -n 50`、需细节 grep 日志；禁止全量输出进上下文。execute `buildWavePrompt`（execute.js:874）加同款示例。验收：R16 均轮 ≤160K（R12 134K 为下界参照）。

## 六、P1-2 砍交互摩擦三件

1. **wait/answer 合并式渲染**：brainstorm 8 步中 4 步带 wait 标记（brainstorm.js:74/202/228/395），渲染的三段式（prompt.js:2066-2081）让 agent 每步跑 wait/continue/done 三条命令。`--done --answer` 一步合并**后端已支持**（complete.js:185-209 resolveWaitingStepWithAnswer）——纯渲染修复：自主模式（非 TTY）下 SS-META doneCommand 与文案改印合并式一条。R15 的 4 次补轮归零。
2. **收口一次性清单**：runStageCompletionGates（gates.js:747）纯文档 blocking 门组（runValidators / module-impact 死信 / 预填注 / Stage Review / design 清单）从串行 fail-fast 改**收集模式**——全跑完、每门保留原错误文案、一次打印、统一 rollback 一次（rollback detail 仍取首门名防下游漂移）；实测门（test/lint/parity/probe）保持最后且 fail-fast。验收：一次 --done 报全全部缺失；R16 收口拦截 ≤1 轮。
3. **worktree 守卫选择记忆**：守卫全是 fail-closed 抛错+文字菜单（worktree.js:721 分支冲突三选一 / worktree-apply.js:1568 overlap 三态 / :1615 stash-dirty），选择不落任何配置、下次原样重拦。新增 local.yaml `worktree.policy` 段（adopt_branch / stash_dirty / apply_overlap: manual|force|skip），三处守卫读取；缺省维持 fail-closed，显式 flag 优先于 policy。

## 七、P1-3 deps 装配带 extras

`worktree-deps.js:78` 裸 `uv sync` 改探测三态：pyproject 有 `[project.optional-dependencies]` → `uv sync --all-extras`；只 `[dependency-groups]`（uv 缺省已含 dev）或皆无 → 维持 `uv sync`；纯 requirements.txt → pip 不变。**白名单零改动**（INSTALL_BINARY_WHITELIST 按 binary 判定，`--all-extras` 无元字符天然放行，已核验 worktree-deps.js:283）。config-schema `commands.install` 描述补说明 + 保留覆盖出口；补单测三态。验收：R16 零 extras 缺失自愈轮。

## 八、P2 四件

1. **verify 入参数对（不收紧）**：材料包 R14 后已收紧（PACK_MAX_CHARS=12000 / 请求预算 12 / 只读纪律 / digest 式 design 摘录，review-material-pack.js:30-32 与语义头）。动作=实证核对 R16 生效 + execute-qa 包补入测试清单（测试文件列表）。**不做进一步收紧**——S2 评审靠定向查证抓了 5 个 P1，过度收紧会掉检出率（每美元检出率定位的推论；R14 失控勘察的教训已被请求预算硬钳覆盖）。
2. **quick 常态化**：classify-change.js:15-28 关键词表扩充 force_quick 默认面（R5R 实证 quick≈OS）；AGENTS.md 规则 6 补一句倾向性表述。
3. **burst 降级注记**：config-schema `stage.burst` 描述补实测结论（往返↓ token↑；stage-runner 落地后肥载荷自然消解，定位体验项）。
4. **设计评审清单加两条**（stage-review-checklist.js）：①承诺可兑现性——design 每个可测承诺逐条过最坏输入四维（乱序/并发/切换/作用域），不能兑现则降级承诺或改取简方案（全量重拉结构性消灭 F-01/F-02 整类）；②三方对齐——spec/design/实现取舍矛盾必须二选一对齐，不许"实现跟 design、spec 跟 design"各说各话（R14-P1-3 / OS 审计③ 同型）。

## 十一、风险汇总
