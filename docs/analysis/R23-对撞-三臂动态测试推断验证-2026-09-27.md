## 门禁形态实录（本轮核心观察面）

- **full 臂（noAI 质量扫描路径）动态子集真实跑通**：「动态测试子集（缺省）：本变更测试 ∪ FR 关联回归 ∪ import 依赖 = 19 个
  （deps 19）；runner 自项目结构推断」「动态子集批 deps(auto-py)」——`module[]+deps(py19)`，uv 环境按 backend/uv.lock
  就近祖先推断，首跑 213.4s 后按代码指纹复用（后续 --done 免重跑）。三源里的 fr(..) 批未出现：载体库 FR 绑定与
  变更触碰面的交集本轮为空（绑定行在 ledger 定格后才补齐，见缺陷③）。
- **thin 臂门禁 1 轮 dynamic-empty 跳过——暴露盲区（缺陷①，本轮最重要发现）**：快照 = `git worktree add --detach <snap> HEAD`
  + overlay 会话文件；thin「先提交再收口」使 overlay 与 HEAD 同内容 → 快照内 diff 只剩真未提交文件（AGENTS.md）→
  与权威面（主仓 baseline..HEAD=15 个交付文件，主仓侧计算正确、已用真函数复算核实）相交后判空跳过。
  旧代码同场景同样盲（full 兜底→无 commands.test→同样 skip）——非本次回归，但动态子集把它从沉默变成有理由的跳过，
  可见性倒逼修复。修法已定：flow done 把主仓算好的权威面以 faceOverride 直传门禁（快照只隔离执行，不重推文件面）。

## 结论

1. **R22 的病治了**：零测试配置下 thin 全程无一次测试门环境拉锯（R22 同场景 11 轮/168 分钟），成本回到 OS 水平线 +12%。
2. **动态推断在 full 流程的 noAI 扫描路径完整跑通**（19 文件组卷、结构推断 runner、指纹复用），无 R22 的 auto-tick 死锁/假阳性。
3. **代价是新盲区现形**：thin 收口路径门禁未实际测到交付面（缺陷①）——修复前「thin 测试门 1 轮」的漂亮数字要打折读：
   那轮是跳过不是通过。修复后需 R24 复验。
4. full 流程成本主轴仍是阶段上下文税（~2.7× thin），测试门优化只削掉了它的重试毛刺——进一步压成本要动长会话结构，不在本系列。
