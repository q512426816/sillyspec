## 三、运行协议（阶段墙手动切割 = R15 已示范的形态，hard 档把提示变硬拦）

```
会话 A：export SILLYSPEC_SESSION_ID=R16-sf-main
        run brainstorm → … → plan --done（出现 ⛔ 阶段断崖）
        sillyspec handoff --change <名>        # 生成交接块
会话 B：新会话粘贴交接块（SESSION_ID 不变！）
        run execute → … → execute --done（再出 ⛔）
        sillyspec handoff --change <名>
会话 C：新会话粘贴交接块 → run verify（独立评审层保持 S2——省钱不省审查）
```

- verify FAIL → `run execute --reopen` → 修复 → **verify 复跑可在同会话**（墙对已初始化阶段的重入放行，修复回路不被墙卡死）。
- 若确需同会话硬续（应急）：`run <stage> --same-session`。

⚠️ **环境坑已修复（2026-09-24 夜，ql quick-ed49698b）**：R16 批次一收口期主仓 node_modules 三次被清空的根因**不是并行会话**，是 sillyspec 自身的门禁快照清理缺陷——`git worktree remove --force` 的递归删在 Windows **跟随 junction**，快照内 node_modules/venv 链接指向主仓真身，git remove「成功」返回且无声删光目标内容（端到端最小复现已钉死）。修复：cleanupSnapshot / 账本回收改为「先解链全部 reparse 点 → 再 git remove → 安全兜底」（src/run/junction-rm.js + 端到端回归测试 gate-snapshot-junction-pierce）。修复已随本批次进全局安装；若实验中再遇 ERR_MODULE_NOT_FOUND 先确认 sillyspec 版本含 junction-rm.js。quick 门禁遇快照病态仍可用 `SILLYSPEC_QUICK_GATE_SNAPSHOT_OFF=1` 主仓口径（有审计留痕）。

### 会话 A 提示词（brainstorm → plan；靶仓根目录开新会话粘贴）

```text
【R16-SF 对撞实验 · 会话 A】你在已配好 SillySpec 的仓库里按流程完成一个变更。先执行：
export SILLYSPEC_SESSION_ID=R16-sf

【任务书】实现「observation events 服务 v3」（在现有后端/前端代码基础上）：
1. 写入端点：批量接收 observation events（每批 ≤500 条），鉴权仅限 shpsync_ token 派生的工作区，body 不收 workspace 字段；按 (规范化 ts, 去重键) 幂等去重；窗口上限 5000 条，超限按接收序剪枝（并发下允许少量超删，design 里如实登记）。
2. 读取端点：可选 since 增量参数——语义基于服务端接收时间（received_at）而非事件业务时间戳（业务 ts 可能乱序到达，基于业务 ts 的游标会永久丢失晚到的早 ts 事件）；缺省返回最近 2000 条并带 truncated 标记；单条 detail 载荷上限 64KB。spec 文本、design、实现三者对该取舍必须逐字对齐（缺省全量还是窗口、上限在哪层，不许各说各话）。
3. 前端：30s 轮询全量重拉列表（不做增量游标）；告警条自动展开每个告警只决策一次（用户手动收起后不再自动展开）。
4. 兼容：未配置新功能时既有行为不变；提供回退路径。

流程规则（实验观测项，必须遵守）：
1. 变更名固定用 2026-09-25-observation-events-v3-r16sf（sillyspec run brainstorm --change <该名> 启动）。严格按 CLI 说明书推进，每步按末尾命令 --done。禁止跳步/裸改产物绕门禁/不确定时猜命令。
2. 需要用户决策的步骤：向我提问拿到答复后，用 --done --answer "答复" 一步收口。
3. 长输出纪律：预计超 50 行的命令（测试/安装/全量 JSON）重定向 .sillyspec/.runtime/logs/ 后只 tail 回看。
4. 阶段墙（stage.wall=hard 已配置）：plan 收口后 CLI 会 ⛔ 拒绝同会话继续 execute——这是实验设计不是故障。此时执行 sillyspec handoff --change <变更名>，把交接块原样输出给我，然后本会话停止（不要再跑任何 sillyspec 命令）。
5. 不要修改 .sillyspec/local.yaml（实验配置已就位）；不要进入 .sillyspec/.runtime/worktrees/ 下其他变更的目录。
6. 每阶段收口后报告一行：阶段名 / 本阶段 CLI 调用次数 / 墙钟。
现在开始。
```

## 八、R16-a 作废记录（2026-09-24 夜，47 分钟中止）

- 作废原因：①靶仓沿用了 `stage.burst: true` 且未配 `stage.wall: hard`——核心实验变量（拆会话）未生效，plan 完成后 agent 同会话直进 execute（上下文滚至 329K/轮）；②模型误用 opencode 免费模型（space-bunny-free，单轮生成 17 分钟，TaskCard×3 与两个 Stage Review 子代理串行排队）——墙钟与 token 与 R15 不可比；③平台同步 409 失效配置污染每条 CLI 输出。

- 清理：worktree --force + change-delete 软删（git 可回溯）；burst 移除、wall: hard 配置并实测；platform disconnect。
