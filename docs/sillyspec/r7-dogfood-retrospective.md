## 二、真防线 vs 仪式税（R7 的保留面与砍除面）

**真防线（抓到真问题，R7 红线保护的就是这些）**：
- Design Grill 独立审查：5 个结构性缺陷（归档复用面一半是步骤名非函数/editRatio 与三态拒收互斥/事件推送通道未定义/registerChange ghost 误判/config-schema 漏注册）——全是设计期真缺陷，无一是格式问题
- execute 独立审查：3 blocker（MAX_LIFETIME_MS 未定义致子进程 100% 崩/套件阀反噬自家测试/legacy_fallback 只读不写）——主 agent 自测全绿之下抓出的
- 机械 gate 正确拦截：doc-ref 行号漂移（3 处，我改代码所致）/lint 未引用导出/module-map 覆盖/质量扫描 fail-closed——每一条都该拦
- 结论：**验收侧守卫的有效率极高**（本次拦截的 12+ 次里，指向真问题或真歧义的占多数；纯格式/模板类是少数但每次都是完整一轮重跑税）

**仪式税（R7 砍除面，本次实测最痛的）**：
- brainstorm 8 步中的 3 个强制 wait（复述冻结决策）；execute 前置 4 步（进度/上下文/worktree/范围确认——上下文已热时零信息增量）
- gate 的模板完整性拦截（缺章节标题/缺 D 引用格式/taskcard 前缀）——这是「生成侧该机器做」的事，agent 手写格式再被验收侧打回，双倍税
- plan 细拆诱导：18 卡/10 Wave 拆给反仪式变更（用户两次裁定才收口到 7 卡/4 Wave——D-06 已修 prompt，本复盘是它的实证注脚）
- 模块卡同步被流程排到收尾一次性做（5 张卡三种格式形态，手工补注记）

## 三、五个问题模式（跨问题的结构提取，供后续变更自查）

1. **双写漂移**：schema live 键 vs renderExample 模板（config-schema 红的主因）/ module-map vs 文件落地（预注册被打回）/ doc 行号 vs 代码行号（3 处漂移）。单一真相源每被违反一次，就多一道 gate 兜底、多一轮打回税。→ R7 切片三机器起草天然消灭生成侧双写。
2. **环境不一致**：worktree vs 主仓（12 项 CLI 子进程类测试环境性红，stash A/B 才证零增量）/ 套件 env vs 裸 env（T1b 的分叉根源）/ 快照 overlay vs 工作区（gitignored local.yaml 中途修改不可见）。同一代码在不同环境面行为分叉。→ 测试纪律：env 敏感测试双模式跑+行为翻转走被跟踪文件。
3. **状态标志写读配对缺失**：legacy_fallback 只写读侧（审查抓出）。→ 状态类 FR 强制写+读成对测试（flow-protocol ⑤ 现在就是范式）。
4. **裁定组合死锁**：失败升厚（裁定#10）× 断点续（裁定#2）各自正确、组合出「升厚后无 plan.md 归档死锁」——born_face 出身/仪式分离才解开。→ 多裁定变更须做组合状态表推演（thin/thick × born_face × 各子步）。
5. **生命周期盲区**：41 孤儿泄漏——设计审查覆盖了 API 面/通道面/语义面，没人审「进程死亡面」。detached 长驻进程的自灭条件（三闸模式）已入 knowledge。→ 设计模板可加一节「非功能生命周期：进程/资源/清理谁负责、何时死」。

## 四、对终验重放的预测价值（本样本的使用法）

- **本次=thick 样本**：三轮用户裁定（五点/收口/GSD 对齐）+grill 5 修正+12 执行问题修复——
  决策密度极高。若 R7 已在场，flow start 的路由判据（即使没有 editRatio，仅凭显式 --thick
  的使用意愿）也应走厚档。**终验重放任务（输入已含决策的转写任务）才是 thin 形态的主场**。
- **协议调用对照估算**：本次 ~40+ 次协议调用 → thin 形态同任务理论 5 次（start/done+1 次
  grill+2 次审查回收）。省的不是步骤渲染，是每次调用携带的全上下文重发（R5-L 桶①口径）。
- **必须保留的成本**：独立审查（3 轮全有真捕获——R7 任何薄化不得动它）；fail-closed 门
  （拦我是对的）；module-map/lint/doc-ref 机械对账。
- **烟测优先级修订**：thin 样本烟测（30min 级小任务）优先级高于重放——先证明薄形态在
  低决策任务上「2 次调用走完且无静默失控」，再测大任务重放的数字。
