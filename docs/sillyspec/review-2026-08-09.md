## 总体判断

地基是稳的——W6 重构无循环依赖、stage 契约一致、better-sqlite3 迁移（commit a7f46c2）已根治 sql.js 时代的 P0 物理并发损坏。真正的债集中在三处：

1. **worktree 链路全仓唯一还在用 `execSync(\`git ${args}\`)` 字符串拼接**——既是空格 bug 又是注入面（4 代理共识）。
2. **「先 persist `completed` 再跑 gate」的崩溃窗口 + `complete-stage` 后门绕过 review gate**——流程正确性核心。
3. **better-sqlite3 只解决了物理写竞争，没解决全量快照 `_write` 的逻辑 lost-update**。

其余是「重构没收尾」型技术债和 Windows 健壮性缺口。

### #1 [P1][安全][共识：B/C/D/E] worktree 链路 git 字符串拼接 → 命令注入 + 空格拆词
- **位置**：`src/worktree.js:70-71,76`（git/gitQuiet helper）、`src/worktree-apply.js:25-27` 同款 helper、`src/index.js:859`（`--base` flag 直接插值）；拼接点 `worktree-apply.js:108/193/261-264/347/356-360/366/369-372/375/402/459`
- **问题**：文件名来自 worktree 工作树（agent 可控 / plan 可诱导产出），`.join(' ')` 拼进 `execSync`：① 含空格文件名被 shell 拆词 → apply 静默漏文件（**确定性 live bug**）；② 文件名含 `;`/`$()`/`` ` `` → 在用户机器上 RCE
- **依据**：同仓 `src/run/shared.js` 的 `safeGit` 已改 `execFileSync('git', [...args])` 数组形式并留注释「数组形式不经 shell：避免路径含空格被拆词」，唯独 worktree 链没同步，口径分裂
- **建议**：helper 换 `execFileSync` 数组形式（复用 safeGit 或本文件重写），文件列表作为独立 argv 元素；补「含空格文件名 apply 不漏」「含 `;` 文件名不触发额外命令」两条回归测试
- **状态**：review-2026-08-08 B 组 P1-2 曾只定性为健壮性 defer，本次 4 代理补上安全维度，优先级上拉

### #2 [P1][共识：F+C] 先 persist completed → 再跑 gate 崩溃窗口 + complete-stage 后门
- **位置**：`src/run/complete.js:262-278`（及 `:720-726`）、`src/run/stage.js:352-358`、`src/progress/stage-machine.js:36-117`
- **问题**：完成分支先把 `stageData.status='completed'` 落盘（complete.js:265），之后才跑 `completeStageGates`（:278）。硬中断（Ctrl+C/OOM/CI 超时）落在中间 → DB 永久留 completed 而 review gate 从未跑。**verify 阶段窗口最宽**（`runVerifyTestCheck` gates.js:208 同步跑全量测试 2~10 分钟），agent 自报「测试通过」的谎话无校验落地
- **叠加**：`runStageCompletionGates` 里 `runValidators`(gates.js:181)、`runVerifyTestCheck`(:208) 两段**无 try/catch**——抛非结构化异常直冒顶层 exit 1，`rollbackStageCompletion` 触达不到 → 同样卡死 completed
- **后门**：`complete-stage`（stage-machine.js:36-117）只跑 `runValidators` 不跑 Stage Review/Task Review/verify-test，产物齐时**不需要 `--force`** 即可标 completed；崩溃恢复路径（stage.js:198）也经此函数
- **建议**：① 落盘 completed 移到 gate 成功之后；② `runStageCompletionGates` 整体包 try/catch 触发 rollback；③ `complete-stage` 收敛到同一 gate 级联或显式 `--skip-review-gates` opt-in

### #3 [P1] 全量快照 `_write` 的逻辑 lost-update（better-sqlite3 迁移未覆盖）
- **位置**：`src/progress.js:385-473`（_write 全量 UPSERT）；读 `read()` :240-365（事务外）；~30 处调用点
- **问题**：`read()`（事务外拿快照）→ 内存改一步 → `_write()`（全量 DELETE-then-INSERT 覆盖）。`db.transaction` 只保证单次写原子，**挡不住两个进程各用旧快照互盖**。触发：两个 agent 对同一 change 并发 `--done`（子代理+主代理）。A 完成 brainstorm/step2 _write，B 用更旧快照 _write → brainstorm/step2 静默回退 pending
- **依据**：`_write` 注释自承「单进程内调用串行」，跨进程 same-change 并发不在假设内；concurrent-write-preflight 是 advisory WARN 且只查 git 脏文件，不覆盖 DB lost-update；`updateStep`（定向 UPDATE）没这问题，但主流程走 `_write` 全量路径
- **建议**：加 `revision` 列 compare-and-swap（版本不符报冲突让 agent 重读重试），或主流程 step 写入改定向 UPDATE（架构级）。与 multi-agent-review D2「tasks.md 共享写无锁」同源，建议合并立项

### #4 [P1] worktree cleanup junction 解链 race → 删主仓 node_modules（Windows，复发坑） ✅ 已修复（commit 0048d21 / archive 2026-08-09-worktree-junction-fail-loud / D-001@v1+D-002@v1 双 fail-loud：lstat EPERM + 解链失败均 throw，_doctorReprovision 废弃 :878 best-effort 不调 provisionDeps；7 用例/18 断言测试锁定）
