## 二、诊断（五条，每条带依据行）

**D1 小任务的浪费主犯是治理三轮（54%）**——82 次协议调用 + 49 轮工件撰写 + 28 轮门禁往返，
写码只占 16%。依据：§1.1、§1.3 SF 行。

**D2 成本机制 = 轮数 × 上下文斜率（超线性）**——每多一轮都在更贵的上下文上计价；SF 把斜坡
爬到单轮 360K，42% 输入烧在尾部大轮。openspec 同机制但 71 轮结束。依据：§1.3。

**D3 大任务主犯是"读"回到主会话满价上下文（30-35%）**——batch2 杀扇出（19→3，42.3M→1.94M）
把子代理新鲜上下文里的读活搬回主会话：主会话 56.8M→134.5M。M4 一刀切 main 模式对小任务对、
对大任务负优化。依据：§1.2、§1.3 R5-L 行。

**D4 环境税被低估（大任务 ~20%，quick 19%）**——python-heredoc 57 轮整文件重注入、worktree
依赖装配缺失。工具侧一次性修复可回收。依据：§1.3。

**D5 质量溢价未兑现**——付了 7-9× 的溢价，防线对域事实类缺陷零拦截（概率性防线也未触发）。
流程税的正当性必须重建或退还。依据：§1.4。

## 三、方案：五刀一底座

### 刀 1 · verify 机器化（定价：大任务 69min + 小任务 60min）

- **改动**：verify-result 九章节由 CLI 进程内组装——测试结果读 P2 test-ledger（已落地，fail-closed
  指纹免重跑）、探针对账跑 verify-probes（机械）、module/symbol-impact 由 diff×module-map 计算、
  known_failures 按签名归因、归档就绪用 batch3 P3 buildArchiveReadinessReport（已交付，接线即可）。
  agent 在 verify 阶段唯一参与 = 偏差与例外段（无偏差则零轮次）。
- **依据**：SF verify 60min（23:24→00:23）；R5-L verify+archive 69min；其中 E 类工件撰写
  verify 阶段占 4.61M（45.8% 的工件 token）。
- **预期**：两任务各回收 40-50min 墙钟 + 对应轮次。
- **风险**：机器报告的例外段语义要设计好边界——只留"agent 解释为什么偏离"，不让它复述机械结果。

### 刀 2 · 2-调用协议（定价：82/79 次 CLI 调用 + 其全部重发）

- **改动**：步进机（brainstorm 8 + plan 4 + execute 14 步）折叠为**启动 1 次 + `--done` 1 次**。
  启动时一次性下发：整段薄流程指令 + 全部材料**路径**清单。中间零协议必需交互；agent 自愿的
  `status/verify` 调用合法但不计入协议必需。配置开关 `flow: thin | legacy`，缺省 thin，回滚一行 yaml。
- **依据**：SF 82 次调用中 `run brainstorm` 系 20 次；R5-L 79 次；每次调用带注入并发生在
  已膨胀上下文上（D2 斜率放大）。
- **预期**：小任务轮数 265→~90；协议轮 token（SF 13.9M）基本清零。
- **风险**：失败反馈后置到 `--done`——对冲：watcher 实时 advisory 警告 + 自愿按需 verify。

### 刀 3 · 工件机器起草 + 薄跑级联（定价：49 轮工件撰写 / 11.7M）

- **改动**：薄跑道（输入已含决策的任务）全部治理文件由 CLI 起草——proposal 从 `--input` 转写、
  requirements 机械摘"成功标准"条目、tasks 机械推导、直写模式零任务卡、decisions 只记真实新增
  （转写任务通常为零）。agent 对草稿只做例外裁决。升级档（三轴判定：输入决策覆盖度 × 爆炸半径 ×
  执行验证可得性）保留完整仪式。
- **依据**：SF 工件输出 60K vs 代码 13K；R5-L 四件套在代码完成后才提交（P15：26/31min 是仪式）；
  EHS 实证 62% 前置。
- **附赠闭环**：agent 对草稿的编辑距离 = 决策覆盖度的机械代理指标（改写过半 → 该走升级档）。
- **风险**：薄跑判定是启发式，首版会误判——兜底 10 秒否决口（`--full`），误判成本一轮。

### 刀 4 · 大任务读活回便宜上下文（定价：R5-L 读轮 40.9-47.2M）

- **改动**：execution_mode 按任务规模分档——小任务 main 直写（维持），大任务回 dispatch 形态但
  按 GSD 纪律：**编排者瘦**（只传路径）、执行者新鲜上下文自读、材料包稳定段先行（B-④ 已落地）、
  派发阻塞回收保缓存热（P14）。不是回到 R4 老 扇出（冷启动 42.3M 的那种）。
- **依据**：§1.2 主会话 56.8→134.5M 的涨幅与读轮占比对齐；GSD 源码对照（round5 归因 §十一）。
- **预期**：大任务主会话回落 ~70-80M，总 token ≤60M。
- **风险**：dispatch 形态的交接税回归——用 M3 分组（已落地）+ 材料包 + 返回契约（已落地）压制。

### 刀 5 · 环境税清剿（定价：R5-L 23.1M +13.9M 装配 / SQ 1.58M）

- **改动**：①Windows Write 工具失效场景修复或 CLI 提供 `sillyspec write` 逃生通道（消 heredoc
  整文件重注入）；②worktree 依赖 junction/硬链接复用（消 node_modules 拷贝与装配失败）；③命令
  前缀税：CLI 侧吸收 cd/export 样板（cwd 与 env 由工具管理，agent 命令裸奔）。
- **依据**：§1.3 python-heredoc 57 轮 17.2%；R5-L export 前缀 88 次；SQ 环境 19%。

### 底座 · 产物 watcher（观测与协议解耦）

- **改动**：change 启动拉起 detached 监听进程（spec-sync-bg 先例），从**文件产物签名**推断
  阶段（proposal→requirements→design→tasks→checkbox 翻格→git 提交→verify 工件→归档移动），
  推平台。watcher = 缓存（best-effort、崩溃降级）；`--done` = 真相（终审对账）。机器起草的工件
  信号更规整。副产品：阶段级墙钟拆账自动采集（产物 mtime 序列），替代 transcript 抽取。
- **依据**：用户指出信道混淆（协议对话与平台心跳共线）；既有教义——tasks.md 唯一任务真相、
  P2 账本、progress db。

## 四、四条协议钉（设计不变量，机械 harness 可验）

1. **协议必需交互 = 2**（启动 + `--done`）——无 agent 的 harness 走通流程数调用；不是对 agent
   的配额，是协议形状属性。
2. **工件回填轮 = 0**——协议不要求 agent 在会话内撰写任何 .sillyspec 工件（机器起草，agent 仅
   例外裁决）；agent 自愿写设计笔记是自由不是违规。
3. **观测事件与协议交互解耦**——watcher 事件来自状态文件/git/工件三类源，数量不随 CLI 调用
   数等比例下降。
4. **薄跑道会话内 .sillyspec 写入仅例外裁决**——harness 验证产物面。

## 五、验收（发版硬门 + 遥测）

- 小任务全道重放：**≤25min / ≤90 轮 / 协议钉 1-4 全过**
- 大任务重放：**≤90min / ≤280 轮 / ≤60M / 读轮占比 ≤20%（回便宜上下文）**
- 质量底线：错键探针套件绿、P2 账本对账一致、12 真拦案例回归、多会话隔离狗食
- 遥测四列（CLI 调用轮 / 工作轮 / 工件回填轮 / 注入字节）：**只记录不判罚**，定位协议肥肉用
- 对 openspec 的目标溢价：10-20%，买到 quicklog 账本、知识检索（导线已上线 ql-011）、多会话
  隔离、fail-closed 测试门

## 六、红线与非目标

**不动**：四道防线判定语义、P2 测试门、allowed_paths 守卫、多会话所有权/worktree 隔离、DB schema。
**非目标**（各自独立立项）：错键防线（事实核验入口，书记员形态——证据链已满：三杀+四道全灭+
FR 典藏）；FR 事实标签（四档核法矩阵已定）。
**诚实边界**：薄跑判定启发式会误判（否决口兜底）；失败反馈后置（advisory 对冲）；watcher 粒度
是产物级非步骤级（消费方核实够用：阶段级+任务级+测试事件级）。

## 七、实施顺序

刀 1（纯减法，零语义风险）→ 刀 2+底座（协议折叠与 watcher 同批，互相成全）→ 刀 3（薄跑级联
+路由翻转）→ 刀 4（大任务分档）→ 刀 5（随时可插）。每刀走完整流程独立落地；**刀 2 起用翻转版
自己的薄流程开发后续刀（自举即验收）**。

## 八、与法证方案的对账（2026-09-22，对 r5l-forensic-verdict.md）

**方法论修正（本方案接受）**：浪费的因果度量 = 对 openspec 的 **Δ**，不是绝对值。法证 Δ 分析
证明读桶基本对称（+6.1M，任务固有），多付的 82.3M 中 94% 是三个流程桶（CLI 往返 +29.1M /

撤回，降级为观察项**——openspec 单会话 51.9M 是形态可行的存在证明，回 dispatch 有重蹈 R4
冷启动税风险。

**裁决记录**：wave 子代理撤回=同意；M1 降级=同意其推理（发命令动作本身即全量重发），注脚

**执行顺序（合并版）**：法证方案 1/3/4/5（quick 四连发）→ 法证方案 2（决策密度轴，完整流程）

## 九、评审吸收·六条（2026-09-22，立项评审意见并入）

1. **R6 判读三层化**：地板门保留（≤20M/≤156min/≤1.8×）+ 达标线（三桶 ≤20M 且当量 ≤1.3×）
   + 拉伸线（≤1.2×）；擦边过关必须附剩余差距归因，不得直接宣布成功。
2. **heredoc 治理走机制不走劝说**：删除一切"勿 heredoc"类 prompt 提示；守卫在 `--done` 验收侧
   ——机器预填段带指纹，`--done` 拒收被整份重写的预填段（显式 `--amend-draft` 留痕例外）。
   事实修正：R5-L 同会话 Write 成功 24 次 + heredoc 58 次，成因混合（部分失效+习惯迁移），
   机制修法对两者均免疫。
3. **task done 原子性**：每子步先查自身完成标记（幂等跳过），失败报告精确到已完成子步；
   验收加中断半态重入用例；ownership 继承多会话守卫。
4. **决策密度轴不对称默认 + 机械升级**：模糊偏厚；薄跑资格机械取证（提案含冻结接口/验收节）；
   不依赖 agent 主动 `--full`——**失败触发升级**：verify 失败/审查否决自动将剩余流程升厚档。
5. **watcher 事件恒带 `provisional:true`**：平台 ingest 只展示不判定，`--done` 为唯一真相——
   防止"面板要更多事件→倒逼协议回肥"。
6. **真拦保护**：③ 签名闸回归五态（同签名拒/代码变放行/**环境变放行**——签名必须含环境探针/
   force 通路/12 历史真拦案例）；对外口径"未买到域事实拦截"与对内口径"测试门为唯一实证价值"
   并存，效率刀不得触及 fail-closed 判定语义。

**设计原则第一条（本评审沉淀）**：守卫必须是验收侧的机制，永远不是生成侧的劝说——本轮对话
三次收敛于同一结论（调用配额→协议形状；禁 heredoc→--done 守卫；--draft 保护）。

## 十、落地核对与门分层修正（2026-09-22，代码级核对后）

1. **状态修正（已核）**：③ RERUN 签名闸**已落地**（1ccf5460，五态回归+环境探针入键+force 旁路）；
   ① `task done` 未存在，胶水型可落；② 是 `--init` 的扩展非新造（探针段已预填+facts 底稿已有，
   任务完成度/风险/测试结果三节仍 TODO），realistic −4~8M 非保证 −10M，`--done` 篡改门禁为承重件；
   ④ 纯墙钟收益（37min 假红），token ≈0，采纳通用化设计（env 钉定缓存链接注册表，uv 为首行
   数据；家目录缺省形态经继承 env 绝对路径直达，不做装饰性 junction）。
2. **效果口径修正**：quick 批次线性加总 ~26-28M（77.7→~50M）；斜坡交互（轮数减少同时压低后续
   轮均价）带来二阶收益，但**不足以闭合至 ≤20M——quick 批次不打穿 20M 门**。此前"五刀→R6
   验收 ≤20M"为乐观合成口径，作废。
3. **门分层重划**：**R6 = quick 批次验收**（现实线：三桶 ≤50M / 墙钟 ≤150min / 当量 ≤1.9，
