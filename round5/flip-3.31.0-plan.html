2质量面：多付的钱没买到东西

三个独立会话（全流程/quick/openspec）写了同一个错键 autoCompactPrecompute（正确名 precomputeCompactionEnabled，官方文档核验）。全流程四道防线——设计自查、计划自查、verify 门、归档提炼——全部放行，错键还进了知识库正典。

所以 3.31.0 的口径改了：贵 10~20% 买的是功能（quicklog 账本、知识检索、多会话隔离、防造假的测试账本），不是"更少 bug"——后者今晚实证为零。防线重建（事实核验入口）是另一个独立立项，不混在这。

3改完后，一次变更长什么样

😵 现在

  1. 走 37 步流程机：每步跑一次命令问"现在干嘛"，每次问都全量重发对话
  2. 每个任务打 4 条命令（开始→实现→记录审查→结束）
  3. verify 报告 九章节手写，被读回 14 次
  4. 环境假失败 → 强制重扫代码没变的测试
  5. 平台靠 agent 打电话才知道进度

🙂 改完后

  1. 开工一条命令：材料一次给全（都是路径）
  2. 干完一个任务 一条命令（四件事 CLI 内部串完）
  3. verify 报告机器算 70%，agent 只填三个空：结论 / 移交 / 例外
  4. 指纹没变不许重跑，拒绝时给四条出路
  5. 平台后台盯文件看进度：proposal 出现=设计、任务勾=完成、账本动=验证
