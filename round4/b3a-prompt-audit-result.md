## D. 解读与瘦身候选（B3a 结论，2026-09-21）

**总口径**：R4-L 主会话 CLI 渲染 204KB ≈ 60K tokens（占主会话名义 56.8M 的 ~0.1%，占峰值的次要面）——CLI 渲染不是 377K 峰值的主因（主因是会话累积），但每次渲染常驻上下文参与后续所有轮次的重发，瘦身仍有正收益。

**证据性发现**：
1. **近重复渲染只占 3%（~6KB）**——「同一指令反复整体重渲染」不是成本大头，各步渲染因进度态不同而不同。去重渲染**不是**瘦身抓手，预期收益上限低。
2. **run 子命令是渲染大头**：53 次 / 98.4KB（步骤指令渲染，单次最大 6.7KB）。同一阶段的步骤指令在 --done 循环中被多次近似重渲染（内容 90% 相同、状态行不同）。
3. **编排者对派发规则是「提取规范、丢弃论述」模式**：CLI 渲染的 workdir 论述段（强制必传 + 破坏隔离后果 + json 范例）转发进子代理 prompt 的字面率为 0，编排者自写成紧凑隔离块（工作目录（强制 ×12 / 禁止读 ×16 / 禁止 push ×12，每条 ~50 字）。行为合规（worktree 隔离全程成立），说明**论述段被读过但未被复述**——其价值存疑但不能仅凭字面率为 0 判死（合规可能正来自读过论述）。
4. allowed_paths 渲染 30 次、转发 0——但审查环节逐 task 对照 allowed_paths 检查（行为消费），属「CLI ↔ 门禁」消费而非 prompt 转发，保留。

**瘦身候选（供 B3b 依审计删减，全部低风险渐进）**：
- **C1（首选）run 步骤渲染增量化**：同阶段同步骤的重复渲染只出「状态 delta + 指令不变声明」，首渲染出全量。预计砍 run 渲染体量 30–50%（≈30–50KB/大任务）。机制级（CLI 渲染器小改），不是删规则——**不动规则内容**。
- **C2（次选，低置信）派发指令论述段压缩**：workdir/隔离的后果论述段压成一行规范 + 一行后果（保留 json 范例与 workdir 值）。省 ~1–2KB/次渲染。风险：论述可能支撑合规——R5 若有隔离事故即回滚。
- **不建议动**：四律请求钳（H3 实证 PASS 承重）、隔离规范行、allowed_paths、testcase-design 段（TDD 引导，taskcard 证据链）。

**方法论修正记录**：v1 transcript 口径因提取稿 700 字截断致规则渲染面全盲（17 签名 15 个零命中假象）；v2 分类正则漏多 flag 前缀；v3 修正后数据可信。B3b 删任何规则前须按本 v3 口径复跑 + 行为级合规核查（字面转发率 ≠ 遵守率，本审计已实证两者背离）。
