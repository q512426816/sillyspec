# R4 五会话全量深读·综合判读（2026-09-21，四子代理并行精读）

## 一、「质量差距是不是小概率」的最终答案：不是，两记实锤

**实锤 1：大任务 OpenSpec 侧存在同类缺陷。** R4-O-L 的 daemon 解析器 registry 键名（`claude-code-transcript-jsonl` 等）是**按命名惯例自造的**，未与上报侧（sillyspec CLI，禁读无法对证）核验；且仓内既有测试常量 `claude-transcript-jsonl` 已经暗示了另一种命名——若不符，解析器永不触发、静默 unsupported，**流程内无任何环节能发现**。与错键（autoCompactPreCompute）同一缺陷类：**外部契约事实未经核验即落码，自洽测试掩护其穿越全部关卡**。两个独立 OpenSpec 跑、两实例——这是系统性暴露面，不是运气。

**实锤 2（最锐利）：两个 agent 生成了同一个错误先验。** R4-S-Q（sillyspec）在 [3.2m] 同样猜了 `autoCompactPrecompute`、[3.9m] 甚至专门搜了这个词——**但先验证再落码**，搜出真名 `precomputeCompactionEnabled`。同模型、同先验、同错误生成；唯一差别是有无验证步。**错误生成是确定性的，拦截是结构性的。**

B 侧错键穿越了六道关卡（proposal→spec→design→tasks→测试→archive），全绿——格式校验不校验事实，文档链越长只是把同一个错复制得更体面。

## 二、效率面的新分解（深读修正）

**R4-L（185min）**：~118min（64%）是子代理扇出等待+后台门禁+额度事故（4 路并发派发触发额度耗尽，中断 ~17min 由用户恢复）；主代理自身生成 <1/3；无效功 ~28min（CLI 旗标摩擦、review.json 两次归位、Wave6 --done 因输出 tail 截断三连跑、verify-result 槽格式学费、嵌套 worktree 下 module-docs-sync 失效、重复 pnpm install）。代码层零返工、15 commit 全净；无联网核验但用本机真实数据（38 个 cursor store.db 全量实测）做了更硬的核验。

**R4-O-L（80min）快的解剖**：零子代理（省 40-60m）+ 决策链短（20-30m）+ 只跑相关测试（10-20m）+ 无视觉验收（10-15m）+ 无独立审查（10-20m）+ 探查前置零返工。反直觉：探查占 24%（快来自读得多）；最大黑洞是环境（venv/转义 ~8m）；最强审查者是遗留测试套件（7 处精确 toEqual 断言逼显式化契约变更）。

**R4-S-F（171min）**：verify 92min 中 **75-80min（82%）是纯门禁运行**（7 次 --done、9 次全量门禁）；agent 有效工作仅 ~15m。三方拆账：CLI ≈50%、agent ≈12%、环境 ≈6%。新发现的结构性问题：① 同一 CLI 内 `gate verify`（独立跑）PASS 与 `verify --done` FAIL 并存——**两套矛盾判定路径误导诊断 16min**；② 「越正确越被罚」——agent 正确地不动并行会话归属的债文件，快照 overlay 因此永远取 HEAD 带债版，门禁结构性奖励越权改他人文件；③ 根因（快照说明+advisory 提示）一直躺在后台日志里，晚读全文多烧 20min。**重跑地板：不改工具 ~60min；修三处（lint 前置/门禁缓存/检查前置）~45min**——全流程与 quick 的合理差距应是 ~20min 仪式成本，不是本次的 130min。

**小任务对（41.2 vs 21.5）**：19.7min 差逐项对平——两轮门禁 +19.9m（纯等待）、存量债清偿 +1.9m、联网核验 +1.2m、stash 对照 +0.6m、终态观测 +1.3m，减 B 的四件套/排障/阅读 ~6.7m。**两侧纯编码测试速度等价**（5-6m）。A 的门禁误拦反而触发正向行为（清债+全量复验拿到 mypy 963 文件级保证）。

## 三、两侧 agent 的真实面貌（修正刻板印象）

- OpenSpec 侧 agent **探索纪律很强**（真实数据探针、搜而不信、诚实披露风险）——缺陷不在 agent 能力，在流程无核验结构。
- sillyspec 侧 R4-S-F 的排障有 15min 绕路（未早读日志全文）、两次被 gate verify 的误导 PASS 带偏。
- B 侧两个真亮点值得吸收：**前端依赖后台安装与改码并行**（墙钟并行度）；**三态下拉表达「键缺省 vs 显式 false」**（语义优于 A 的不对称 checkbox）。

## 四、修复清单增量（在已办五项 + 两缺口之外，新增）

1. **`gate verify` 与 `verify --done` 判定路径统一**（矛盾输出，16min 级误导）
2. 门禁失败输出 tail 截断问题（Wave6 三连跑根因）——失败时给全量日志路径提示
3. 嵌套 worktree 下 module-docs-sync 失效（24 文件全未匹配）
4. verify-result 槽格式旧版拒收的一次性学费（--init 提示要更早）
5. 编排层：并发派发上限感知（4 路齐发触发额度耗尽）
6. （对 OpenSpec 的镜像建议，供对比参考）：外部契约事实表 + 来源强制校验 + vendored sdk.d.ts 的 10 秒 grep 检查——错键当场现形

## 五、方法论沉淀

「验证全在模型侧（自愿）」与「验证全在机器侧（盲跑）」恰好各错一半——两个流程的真正差距不是仪式多少，而是**防线是否对准缺陷类**：OpenSpec 六道格式关零事实核验；sillyspec 有事实核验结构但机器门禁 40%+ 假拦+双跑浪费。
